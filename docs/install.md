# Fresh Arch installation runbook

This is a guided installation, not permission to wipe or modify an existing machine. Review each stage. The repository contains no partition/format/reboot commands. Keep a working USB/rescue path and the hardware audit accessible off the laptop.

## 1. Before wiping

- Back up anything irreplaceable, especially configs and documents not pushed elsewhere.
- Ensure this repo has been pushed to a remote or copied to another machine/USB. Creating a local Git repo does not make it available after wiping the SSD.
- Save the working MiniBook audit; test its manual checklist while the old system is available.
- Do not put secrets, iwd wireless profiles, or Tailscale machine state in Git. Plan to reconnect/re-authenticate.

## 2. Archinstall choices

Intended defaults:

- UEFI, **Limine**.
- **Ext4, no encryption**. Filesystem selection is handled by the installer, never this repo.
- Normal user with sudo access.
- Standard kernel and Intel microcode/firmware for the audited N100 MiniBook.
- Hyprland, but **no competing display manager**: Ly is configured in a separate stage.
- Networking: iwd + networkd + resolved, **not NetworkManager**. If the installer offers copying the live ISO's network configuration, review what it actually copies/enables. Wi-Fi association, IP configuration, and DNS are separate requirements.
- Ensure Bash, Git, Make, and sudo are available. They are prerequisites for running the repo stages.

Installer menus/version behavior change. Review the generated configuration together before pressing Install. Do not assume selecting a desktop profile has chosen the desired greeter or networking stack.

## 3. Pre-reboot boot checkpoint — required

Verify the actual boot files generated by *your version of archinstall*:

1. UEFI entry/fallback points to Limine on the new ESP.
2. Limine menu configuration includes `interface_rotation: 90` for the MiniBook.
3. The kernel boot arguments include `video=DSI-1:panel_orientation=right_side_up`.
4. Root filesystem/partition references match the new disk. Do not copy the old `cryptdevice`, mapper paths, Btrfs root flags, hashes, or machine-id-based paths.
5. Determine whether the installer uses a UKI or separate kernel/initramfs files and where it obtains its command line. A menu edit alone may not update an embedded UKI command line.
6. Confirm there is working kernel/initramfs update integration; installing the Limine binary alone is not sufficient. Verify an updated entry/image is produced after updates.
7. Test console/Ly orientation separately. The audit found no explicit `fbcon=rotate:` setting; a correctly rotated menu/desktop does not prove the console is correct. If needed, test console rotation rather than guessing its direction.

**Boot changes are intentionally not automated in this initial repo.** We must inspect the actual generated layout before implementing safe automation. First boot should be tested with a recovery USB available.

If archinstall has no suitable kernel-update integration, the separately reviewed AUR `limine-mkinitcpio-hook` is a candidate. Read its current documentation and existing hooks first; do not mix independent entry generators. To expose it in the package selection:

```sh
make aur-plan PACKAGE=limine-mkinitcpio-hook BOOT_HOOK=1
# Only after reviewing the hook's documentation and planned configuration:
make aur PACKAGE=limine-mkinitcpio-hook BOOT_HOOK=1
```

Installing a boot hook can regenerate boot files immediately. Review its scripts and planned configuration **before** installation. This does not enable snapshots.

## 4. Fetch and inspect the repo

Log in as the normal user. Clone the saved/published repo. `make` must run from its root.

```sh
make plan HOST=minibook
make diff HOST=minibook
```

The initial T14 profile cannot be applied; audit it first. Package installation/apply will refuse an existing Omarchy installation, even if manually invoked.

## 5. Official packages

```sh
make packages HOST=minibook
```

This performs a full `pacman -Syu --needed` transaction, not a partial upgrade. Pacman may prompt about conflicting packages; do not blindly accept removals. Regular upgrades are separate deliberate operations, not a reason to rerun the entire bootstrap.

Default development stack is enabled. Use `DEV=0` consistently if you want to omit it; `EXTRA=go` adds Go. Keep Node ownership deliberate: the Linux list uses Node 24 LTS, not NVM plus another Node installation.

## 6. Reviewed AUR packages

Install Paru once as your normal user. The official-package stage supplies Git and base-devel. The target follows [Paru's source installation](https://github.com/Morganamilo/paru#installation):

```sh
make paru HOST=minibook
```

`make paru` preserves an existing helper. Otherwise it asks before fetching the AUR checkout into `~/.cache/arch-setup/paru`, prints PKGBUILD/install scripts for review, and asks before running `makepkg --syncdeps --install` as your user. Inspect other build files in that directory too. Existing matching checkouts are kept without pulling/resetting; conflicting or modified tracked files are refused. Building Paru may install Rust build dependencies.

Then preview and install the selected AUR packages:

```sh
make aur-plan HOST=minibook
make aur HOST=minibook
```

The default selection is `sioyek-appimage`, `brave-bin`, `1password`, `hunk`, and `minibook-support-git`. To select just one declared package, use `make aur PACKAGE=brave-bin HOST=minibook`.

- `make aur-plan` is read-only and works without Paru installed.
- `make aur` asks once, then runs `paru -S --needed --review --aur` with the selected package names. Paru handles fetching, dependency resolution, builds and installation, using its own cache.
- Review PKGBUILD/install scripts and relevant patches in Paru before accepting builds. `--review` keeps review enabled even if your Paru configuration normally skips it; prompts remain interactive.
- Run as your normal user. Paru requests sudo for package installation as needed. A missing Paru command stops the AUR stage with instructions to run `make paru` first.
- Old `~/.cache/arch-setup/aur` checkouts from the previous workflow are no longer used and remain untouched.
- The older cached MiniBook installer referenced obsolete `moused.service`; inspect the actual downloaded revision rather than assuming it is corrected.
- AUR scripts may start services during installation. In particular, tablet daemons can grab keyboard/trackpad input: install/review deliberately with a recovery console and alternative input available.

Brave and 1Password can alternatively be installed through official vendor repositories if explicitly selected later. This initial list does not silently add vendor signing keys or package repositories. Set up the Brave extension, 1Password sign-in and browser integration interactively; do not pass credentials through the agent or commit them.

## 7. Editable config repositories and copied files

```sh
make sources
make diff
make apply-user
make apply-system
```

`make sources` clones personal config repos and OMZ. It never pulls/resets matching existing checkouts or overwrites unrelated directories. The personal pi checkout can coexist with ignored auth/session data; do not re-add such state or change its remote blindly.

Inspect your existing `.zshrc` locally: its contents are intentionally suppressed from diff output. The repo's shell config sources private `~/.config/zsh/secrets.zsh` if present; that file is not copied or created. Keep it mode 600.

Copy stages back up each replaced target, record recovery paths, and leave ordinary editable files. The system stage selects iwd/networkd configuration, the resolved stub symlink, zram, and the Ly UWSM session. It does not delete competing configuration files: on a non-pristine system, inspect existing networkd matching files before proceeding.

Hyprland config uses the Lua API from the currently installed 0.56 sample. Future versions may change it. Applying while a GUI session is active reloads/checks Hyprland; errors stop the stage and leave recorded backups for reviewed recovery. For a first install from a console, validate on the first graphical login.

## 8. App layers outside pacman

```sh
make pi
make herdr-fetch
# Read ~/.cache/arch-setup/herdr-install.sh; review the printed SHA256.
make herdr-install
make herdr-plugins
make doom
make shell
```

Each target asks separately. Existing pi is preserved; existing Doom core/legacy Emacs paths require manual inspection instead of overwrite. OMZ came from `make sources`, which does not run its shell-changing installer.

Doom core/config/package layers are distinct. After install, run Doom's sync/doctor commands through its CLI as appropriate. Because the personal Doom configuration is its own repo, adjust stale LaTeX modules or platform-specific commands there—not by editing its generated state. Typst/Tinymist are the intended writing tools.

The Herdr config expects the Vim-navigation plugin; verify graphics in Ghostty and navigation with Neovim. A real console session does not have Ghostty's graphics/clipboard capabilities.

## 9. Enable services and first graphical session

```sh
make services
```

Requirements checked before activation:

- System files match the reviewed manifest.
- No active/enabled NetworkManager, dhcpcd, or another display manager.
- Required host tablet-mode services are present.
- Ly's selected template unit exists.

The stage masks `getty@tty2.service` for Ly, enables desired services, and uses no `--now`. Other consoles remain available. It does not reboot. Select **Arch Hyprland (UWSM)** in Ly; Ly also provides a shell entry for console-only sessions. Do not start UWSM inside an existing graphical session.

Reboot manually when the boot checkpoint is satisfied. Enablement takes effect on the next boot; if performing setup without rebooting yet, start services individually only after reviewing their effects.

After networking is up, launch Impala to connect. Start/reuse Tailscale and authenticate interactively with its CLI; review route, exit-node, DNS, and SSH settings rather than accepting an inherited identity. This repo does not automatically enable Tailscale SSH or advertise routes.

## 10. Acceptance checks

```sh
make check
make boot-check
```

Missing/drift reports are not automatically repaired. `make check` returns nonzero for missing packages/apps/services or file drift; review every finding.

Then manually test:

- Ly/console/menu/desktop orientation; touchscreen corners.
- Function keys, brightness, audio/mic, keyboard backlight.
- Fold/unfold: keyboard and trackpad disable/re-enable.
- Wi-Fi, Bluetooth, Tailscale after reconnect and wake.
- Lock-before-suspend, lid behavior, resume display, sleep drain.
- USB-C charging and external monitors (must not inherit the internal rotation).
- Brave, 1Password extension/app integration, GUI Doom, Neovim, Sioyek.
- uv projects, C/raylib builds, TypeScript tooling, Typst preview.
- Updating the kernel actually updates the deployed boot image/entry.

Keep recovery media available until the machine passes. The script tests are not a hardware or boot certification.
